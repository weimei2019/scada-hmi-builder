# 从图纸 / 资料到三维场景

## 一、输入分三类，用法不同

| 资料 | 给你什么 | 注意 |
|---|---|---|
| P&ID / 工艺流程图（PDF / DWG） | **工艺流向、位号、设备表、仪表圈、阀门、联锁文字、管径管材** | 是示意图，没有真实位置；先画流向 |
| 竣工图 / 施工安装图（DWG） | 设备平面布置、管道平面 / 标高、泵组布置、管径、管底标高、哪些利旧 | 真实比例很紧凑，直接照搬会拥挤（见 §四） |
| 设备采购申请单（xlsx） | **唯一设备编号、型号、数量、参数、品牌、材质、变频、装机 / 运行功率、备注** | 台账以它为准；常含与组态无关的页（如化验室清单） |
| 客户 / 同事的修改建议（PDF 截图 + 文字） | 对已有画面的逐条修改（泵位置、进出口方向、管数量、颜色、标签、缺什么） | 逐条编号落实，最后按条回复“怎么改的 / 没法改的原因” |

## 二、PDF 图纸

- A2+ 矢量图常常**没有文字层**（`pdftotext` 为空）：`pdftoppm -r 400 -png` 转成大图，必要时**旋转 90°**，再用 PIL 切成 6 块左右放大看；`PIL.Image.MAX_IMAGE_PIXELS = None`。
- 逐块读：设备表（位号 / 型号 / 参数）、仪表圈（功能字母 + 回路号，如 LIRSA / FIR / PI / AIRSA / PIS / LSA）、阀门类型（手动 / 电动 / 止回）、管径管材、箭头方向、虚线（信号线）、“利旧”字样。
- 小字读不清就**直说读不清**，不要猜（曾经把一个接口牌猜成“大气冷凝水”，被用户纠正为“车间来水”）。常识补全要问用户或标注。
- 进水来源这类图外信息，用户一句话就能给；与其猜不如先问。

## 三、DWG 竣工图（本机没有 CAD 软件也能解析）

```bash
conda create -n dwg -c conda-forge libredwg -y         # 开源 LibreDWG，含 dwg2dxf
~/miniconda3/envs/dwg/bin/dwg2dxf -y -o x.dxf x.dwg     # 几秒；DIMASSOC 之类 Unhandled 警告可忽略
pip install ezdxf
```

```python
doc = ezdxf.readfile('x.dxf'); msp = doc.modelspace()
# 统计：实体类型、图层（72 个很正常）、块；文字：TEXT.dxf.text / MTEXT.plain_text()（含代理字符要 re.sub 去掉再存 JSON）
# 图名：搜“（1:xx）”；设备位号：按图层名里含“位号”的文字；管线说明：搜 “DN\d+”（带管径、材质、管底标高）
```

- **图纸里的坐标是真实毫米**（按图幅 1:1 画的），平面图与管道图是同一布局的两份拷贝，y 有固定偏移（用同一个设备文字的两处坐标求差）。
- 渲染窗口图：`ezdxf.addons.drawing`（Frontend + MatplotlibBackend）；**先按窗口筛实体再画，否则要几分钟**；文字 / 块里的汉字在 matplotlib 里是方框，自己 `ax.text` 叠加中文（`NotoSansCJK` 字体）。大窗口出图很慢，放后台。
- 竣工图里的**建筑 / 池体名称常在块定义里**，模型空间文字读不到；位置只能靠管道说明（“去 X 池”）+ 相对关系推断，**推断的位置要在交付时标明**。

## 四、从资料到布局：三步

1. **画流向图（拓扑）**：设备 → 管线 → 设备，每条管线注明介质、管径、方向、起止设备；缺口（如主出水去向）写进待确认。
2. **取相对位置关系**：谁在谁的东 / 西 / 南 / 北、谁在池顶、谁是并排 / 上下。把这些关系保住，比例不要求。
3. **展开成清晰布局**：设备区按 2–3 倍展开，设备之间留出名称牌 / 数值牌的空间；远处建筑压缩；先出全景，再检查标签是否重叠，重叠就挪设备 / 挪牌，不要靠放大解决。保留“竣工图比例版”作 `?layout=asbuilt` 对照，不删。

## 五、坐标换算与批量改位置

- 图纸毫米 → 场景米：`sx = cx + (x − x0)·k/1000`，`sz = cz − (y − y0)·k/1000`（图纸 y 向北，场景 −z 为后），`k` 为展开倍率。
- 批量平移 / 拉开前后排时，用脚本解析 plant 文件里 `add(...)/tag/name/flow/pipe/zs:` 的 z 参数统一加偏移，不要手改几十处；改完用 `node --check --input-type=module < file.js` 查语法，再截图确认。

## 六、从采购单 / 台账同步的字段

设备唯一编号（页面详情里显示）、型号、流量 / 扬程 / 功率、品牌、材质 / 介质（如含固率）、变频、装机 / 运行功率、数量（决定几台泵 / 几个流量计）、备注（利旧 / 先考虑利旧 / 电源接哪里）。数量变了，三维里台数、点位清单、联锁都要跟着变。

## 七、修改建议怎么落地

逐条编号，做一张“建议 → 改动”对照表（回复里给用户）。常见几类：
- **设备位置 / 朝向**（泵装池顶、进口在下出口在上）：改位置和 `rot`，管线从新的接口起；用户没给图时按字面做，并在回复里说明“如果是整台翻转请告诉我”。
- **管线数量**（“2 根管子”“一台泵对一个反应器”）：拆成独立管线 + 各自流量计，不要合用一根。
- **颜色**：避免和相邻介质相近（例如药剂管与污泥管同为橙色会被指出，要换色）。
- **补设备 / 点位**（缺外排泵、缺流量计、三点料位）：加模型、加台账、加点位、加仿真。
- **标签 / 箭头方向 / 名称**：按资料里的正式名称改（图纸上叫什么就写什么，不要自己改叫法）。
