# 台账 · 仿真 · 联锁 · 报警 · 状态

把**与画面无关**的东西放进 `js/<name>-sim.js`：台账 `DEV`、运行状态、控制、工艺模型、仪表值、报警限、报警。画面只读它。接真实 PLC 时替换这个文件的数据来源即可。

## 一、设备台账 `DEV`

```js
def(id, { kind: 'pump'|'mot'|'valve'|'press'|'tank'|'inst', tag: 'P101-A', name, kw, spec: [[键,值],…], vfd, hz, grp, lock: '联锁 / 说明' })
```

- `spec` 放铭牌（设备编号、型号、流量 / 扬程、功率、品牌 / 材质）；`lock` 放联锁和工艺说明（详情卡底部展示）。
- 仪表 `INS(id, tag, name, 量程, 单位, 小数位)` 登记到同一台账，位号用图纸上的原文（LIRSA 101、FIR 102-A、AIRSA 102-A、PIS 203A…）。
- 与点位清单同源：`tags.csv` 由台账导出（设备给 运行 / 自动 / 故障 三个 DI，变频泵加频率 AI，仪表给 AI，顺序设备给工序 STRING）。

## 二、运行状态

```js
D[id] = { run, fault, auto, rt(累计运行秒), hz }      // 泵 / 电机 / 电动阀（阀的 run = 开启，fault = 卡死）
X[id] = { ph: 'idle'|'feed'|'squeeze'|'dump', t, p, auto }   // 顺序设备（如压滤机）
S = { t, demo, L:{各液位}, pH:{…}, F:{…}, hist, alarms, active, … }   // 过程量
const run = id => S.demo && D[id].run && !D[id].fault
```

- `demo=false` 表示通信失败：全设备“离线”，数值 `--`，不推进仿真。

## 三、控制逻辑（`control(dt)`）

- **备用 / 并联泵** `duty(ids, n, want)`：在自动、未故障的泵里选 n 台运行，已运行的优先保持，按累计运行时间轮换；有泵故障时备用泵启动**写一条信息事件**（“P101-B 备用泵自动投运”）。手动模式的泵不被自动接管。
- **单台** `single(id, want)`：只在自动时由逻辑控制。
- **液位带回差**：`hyst(key, v, lo, hi)`，高于 hi 为真、低于 lo 为假，其间保持，防抖。
- **顺序控制**（压滤机：进料 → 压榨 → 卸料 → 待机）：状态机 + 计时；**每个动作要有执行条件**（泵在转 + 阀开 + 源罐有料），条件不满足就不推进（手动关阀会使进料停滞——这样阀门才不是摆设）；一台泵对多台设备时同一时刻只服务一台，轮换最少使用的。
- **PID**：被控量到设定值（如 pH 9.5）→ 调变频泵频率（20–50 Hz），一阶滞后 + 小噪声；每个反应器各用各的泵就各自一套 PID。

## 四、工艺模型要点

- 过程量用**一阶滞后**逼近目标：`x += (tgt − x)·(1 − exp(−dt/τ))`；加一点噪声。
- **时间加速**：`SPEED = 120`（现实 1 s = 工艺 120 s），否则液位 / 药耗看不出变化。
- 来水加慢变化 + 泵出力滞后（`qlag`），液位才会起伏而不是顶死或抽空。
- 药剂 → 指标因果：加药不足 → pH 低 → 出水指标恶化；泵停 → 对应指标恶化。这是用户最爱演示的联动，一定要有。
- 储罐耗量按“设计耗量 / 时间加速”算，别让几分钟内空罐。

## 五、状态与报警

- **设备状态** 三态：正常 / 异常 / 离线。名称牌前圆点 `st-ok / st-fault / st-off`；没有名称牌的设备补小灯（`nolamp` 的除外）；异常红灯闪烁，离线灰且停转。设备**本身不染色**。
- **报警限** `LIM[点] = [低低, 低, 高, 高高]`：低低 / 高高 = 报警（红），低 / 高 = 预警（橙），null 表示无；用 `lvl(k, v)` 返回 `'' | 'warn' | 'alarm'`，数值牌跟着变色。
- 报警列表：`{id, level a/w/i, text, t, ack, clr}`；新报警置顶、恢复置 `clr`、点击确认；故障设备 id 前缀 `f` 单独管理；信息事件直接 `ack/clr`。
- “模拟异常”：优先选**正在运行**且有备用的设备让其故障（展示备用切换），再选其它；“故障复位”清全部故障并把报警置恢复。
- 报警限值图纸上常没有，**自己定的值要标为暂定并让用户确认**（出水指标限值按现场排放标准整定）。

## 六、预热与跑稳

- 页面加载前先 `warmup(150)`：快进 150 s 工艺时间（`step(0.5)` 循环），再清空报警，让趋势图和液位一开始就合理。
- 写一个 node 脚本把 sim 模块复制成 `.mjs`、去掉 `location`，`step(0.5)` 跑 6000 次，统计各液位 / pH / 指标的 min–max、压滤机各台完成周期数、是否有报警、有无 NaN。**这是改仿真后的必做检查**（第一版曾出现：氯化钙罐很快抽空、料仓两分钟见底、压滤机永远只用前两台）。
